# Review a Pull Request

## Procedure

1. **Read the bundle from the base tip:** Run `git fetch origin <base>` and read [AGENTS.md](../../../AGENTS.md), this file, and the rule files that step 3 routes to from `origin/<base>` (`git show origin/<base>:<path>`), not from the checked-out pull request branch, which can carry a stale copy. Read the pull request's own copy only when the diff changes `docs/review/` or `AGENTS.md`.
2. **Pass 1 (Code and full-repo search first):** Inspect the diff, read modified files in full, apply [AGENTS.md](../../../AGENTS.md), and search the repository (`rg`/`grep` callers, sibling implementations, `pkg/common/`, `config/charts/`, tests, and docs) to catch logic bugs, edge cases, concurrency races, and contract mismatches directly from source code. Record all verified Pass-1 code findings before opening any Stage-1 rule file.
3. **Pass 2 (Targeted non-code decisions - supplement only):** Match `git diff --name-only` against `# Diff-path to rule-section routing`, ignoring paths routed to `None (AGENTS.md and repo search only)`. Load `0` rule files when all touched paths route to `None (AGENTS.md and repo search only)` (including test-only, doc-only, build, and CI diffs); otherwise load only the `1` to `2` matching rule files under `docs/review/rules/` (capping at the `2` files for the primary changed packages on cross-cutting diffs; there is no always-load file).
4. Apply a Stage-1 rule only when its `When:` condition appears in the diff. Stage-1 rules are strictly additive to Pass 1: matching `0` Stage-1 `When:` triggers means only that no non-code rule fired, and must never drop, suppress, or downgrade verified Pass-1 code, concurrency, caller/callee, or test defects.
5. Respect settled exceptions on `- Accept:` lines, and do not enforce unsettled debates on `- Open:` lines as policy (mention them at most as a neutral note when directly touched).
6. Write natural code-focused review comments without citing internal `docs/review/` rule IDs or filenames. Never load `docs/review_playbook.md` or `docs/review/provenance.json`, and do not glob `docs/review/**` or open unreferenced files under `decisions/` or `open_questions/`.
