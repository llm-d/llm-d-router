coordinator: `replace-media-urls` now accepts `audio_url`, `video_url`, and inline `input_audio` alongside `image_url`, and routes audio and video through the same encoder pipeline as images. New per-modality step params cap downloads (`max_image_download_size` / `max_audio_download_size` / `max_video_download_size`, overriding `max_download_size`) and replace the built-in MIME allowlist (`allowed_image_content_types` / `allowed_audio_content_types` / `allowed_video_content_types`); audio and video downloads also check the origin's `Content-Type`, while `image_url` stays permissive unless one of its params is set. The shipped `config/coordinator/coordinator.yaml` sets `max_multimodal_entries: 8` to bound what a single request downloads; the code default stays unlimited, so a config that omits the key is unaffected. On the generate path, a `features` map whose `mm_placeholders` or `kwargs_data` names a modality absent from `mm_hashes`, or names a modality with an empty string, is rejected as a client error rather than silently dropping that modality from the prefill and decode bodies.
