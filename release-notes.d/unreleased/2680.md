The precise prefix matcher walks the in-memory KV-block index in place (`kvblock.KeyWalker`) instead of materializing `Lookup`. The `score_tokens` span attributes `blocks_found` and `block_hit_ratio` report the longest contiguous prefix one candidate endpoint holds, in block positions, instead of the number of distinct requested keys any candidate holds; `lookup_hits_total` and `max_pod_hit_count_total` record the longest contiguous prefix once per successful match under `EnableMetrics`. Direct `Lookup` calls and cancelled matches do not increment these counters. Index reads refresh key recency once per read instead of once per key. `lookup_latency_seconds` measures the full `Lookup` or `WalkKeys` call, including walk callbacks. The matcher span uses `llm_d.kv_cache.prefix_match.longest_chain` for contiguous prefix length; `llm_d.kv_cache.prefix_match.keys_found` is not emitted. An omitted or non-positive `inMemoryConfig.podCacheSize` selects 10 pod entries per key, so a configuration containing only `size` supports admissions.
