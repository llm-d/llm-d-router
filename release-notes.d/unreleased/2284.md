You can now assign requests waiting for pods to start a separate, usually longer flow control timeout, while keeping the existing timeout for requests waiting on an already-running but saturated pool:
- Pool has no endpoints: `noEndpointRequestTTL` controls how long a request waits.
- Pool has endpoints but they're all busy: `defaultRequestTTL` controls how long it waits.
- An existing `defaultRequestTTL` continues to govern both regimes until you split them
